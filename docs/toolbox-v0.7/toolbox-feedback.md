**v0.7 feedback after rerunning the posting benchmark and testing company websites**

The update is better. On the same ten original posting targets, the previous optimized site recipe returns four original pages, up from two in v0.6. A3COM and NOOTA's ISCOD pages are now inspected and returned. The stock query recipe still returns two. Confidence is more conservative: ADVANCED Schema's missing parsed employer is no longer certified from its search snippet. These are extraction/identity improvements, not evidence that all four employers or live openings have been independently confirmed.

Verified fixes include the category-flood fallback control, ISCOD routes, separate Lever application destinations, requested/effective page caps, explicit keyword mode forwarding, and structured contract/location conflicts. The real Theodo internship now scores 29/unresolved rather than 95/likely when `contract_type="CDI"` is supplied; the CDI candidate scores 100. The Nantes Capgemini page is also capped at 29 for a Paris request. Keep passing the structured contract: a title containing “CDI” alone still does not trigger that constraint.

The most useful remaining work is below. No toolbox or tracker source was edited for this review; reproductions and profiles live alongside this file.

1. **Supply the domain/site scope to job-query templates.** `core.py:discover_job` calls `profile.queries("job_queries", company=..., title=..., location=...)` without a domain. A profile containing `site:{domain} {title}` therefore produces zero query forms, even with a confirmed employer context. The result reports zero query count/budget, rather than explaining the missing template value. This is why a generic company-site profile currently needs a binder that inserts a literal site scope first. Consider an additive `search_scope`/site-prefix input, and populate the supported domain template from evidence-backed context when available. Shared ATS sites need company path prefixes such as `jobs.lever.co/theodo`; the entire host is not one employer. Explicitly flag a configured query skipped due to missing inputs. Reproduction: `controls.json:domain_placeholder`.

2. **Preserve keyword order through candidate selection.** Standalone search correctly puts the Python result before a Java result when Python has +50. `discover_job` then sorts eligible candidates by their original provider `rank`, reversing that order, and a one-page cap fetches only the Java page. Preserve the keyword-ranked ordinal or an explicit combined score after route classification. This also matters when merging multiple queries: rank one of a later query should not silently outrank an earlier keyword-selected result unless that policy is intended and reported. Reproduction: `controls.json:preferred_order`. The generic profile therefore uses no decorative positive weights; those should be retested after this sort is corrected.

3. **Fix explicit seniority matching.** A synthetic `Senior Python Developer` page receives 95/likely for `Junior Python Developer`, even with `seniority="junior"`. The seniority check uses `_terms(job_title)`, while `_terms` removes both junior and senior as stop words; the contradiction disappears before the check. Detect seniority in the original normalized title, independently of the title-similarity token list. Reproduction: `controls.json:seniority`. A distinct regression should cover both junior→senior and senior→junior; title shortening must not erase either constraint.

4. **Recognize ordinary employer job descriptions without requiring a narrow phrase list.** [ipso's Django/Vue posting](https://pro.ipsosante.fr/fr/rejoignez-nous/developpeur-euse/developpeur-web-fullstack/) is retrieved at rank one by three query variants and has a detailed job description, title and contract. Nevertheless, the unknown-route inspection rejects it as `not_individual_posting`, including when it is the sole supplied seed. It lacks JobPosting schema, exposed HTTP application links, and the current exact description phrases. It uses language such as “votre rôle” and “nous cherchons”; a mailto recruiting route also does not become an HTTP application link. Expand scoped job-description evidence while retaining the distinction from category pages. Do not turn generic recruitment wording anywhere on a page into proof of a single vacancy. Reproduction: `company-native-runs.json`, case `ipso-django`, `reference_seed`.

5. **Reject generic careers pages and validate geographic extraction.** During the same ipso run, the generic `/rejoignez-nous/` page is returned as a posting candidate, while the individual reference is rejected. Its heading “rejoignez-nous” is not in the generic-heading set. The reference parser also extracts `sur l` as a location from “localisation : sur l'un …”; that would create a false hard conflict against Paris. Treat incomplete/unparsed prose as unknown, record a bounded evidence excerpt, and only make geographic conflicts hard when the extracted value is meaningful. Use card/section counts or schema relationships to distinguish a careers index from a single vacancy. Evidence: `company-native-runs.json` and `company-page-audit.json`.

6. **Keep the tests genuinely offline.** The untouched suite produced 124 passes and one failure in `test_rate_limited_host_defers_sibling_not_observed_429`. That test supplies short `/jobs/101` and `/jobs/102` seeds, which are inspect routes rather than recognized specifics. Discovery searches before reading them, but the test never mocks the provider. A real search result caused an additional fetch invocation and failed the assertion. With an experiment-only default-empty provider guard, all 125 tests pass. Set `job_queries=[]` for the isolated seed/cooldown test or mock its search provider explicitly; use a suite-wide fail-on-unmocked-network guard to prevent recurrence. Neither the shipped tests nor production code were modified here. Evidence: the run summary and `offline_provider_guard.py`.

7. **Watch the cost of permissive inspect routes.** The stock recipe now makes 41 recorded page calls across ten applications versus 15 in the previous benchmark, while still returning two exact originals. The optimized recipe makes twelve calls and returns four. The added routes recover useful alternatives, but also inspect category pages, portfolios, corporate product pages and unrelated jobs. Require enough role/employer/source evidence before spending a page slot; keep route rejection and returned candidates distinct from exact or likely matches. More recognition should not become unrestricted crawling. A query/source profile is worth selecting before raising the page cap.

8. **Use an actual scope boundary in addition to `site:`.** All forty company-site query observations happened to stay inside their requested scopes. That does not make a search operator an access or identity boundary. The prototype filters candidates and redirects by host plus path prefix before accepting them. `Settings.allowed_hosts` can enforce hosts for network requests, but cannot distinguish two employers on a shared ATS host by path and is instance-wide rather than per operation. An additive per-call candidate/scope boundary would fit the shared asynchronous host architecture. Do not confirm a shared ATS host as an employer domain; retain its provisional association and use page-level employer evidence.

9. **The generic company profile should remain separate from board profiles.** The best training-selected company sequence was employer name plus short role, then short role plus hiring vocabulary, both scoped to the company website or verified ATS path. It recovered seven of eight known reference URLs and returned six individual reference pages; the two held-out website cases yielded no exact returned references because of the ipso parser miss and SFEIR's old ID being absent from the new search results. These are eight published reference pages across six scopes, not another ten tracked applications. Do not claim a universal success rate. Keep full original title, contract, reference and location for final matching, using `search_title` only for search.

10. **Unsupported media and repeated variants still cost slots.** INTM's broad site results include several PDF job publications; the HTML fetcher continues to reject them. Preserve that format outcome rather than calling it no vacancy. Some ATS results also duplicate a UUID with tracking queries that normalization does not strip. A structured unsupported-media reason and evidence-preserving URL/ID deduplication would make the page cap more useful. Do not blanket-exclude all PDFs when they can be the only publication of a vacancy.

The generic profile is ready as a bound, tested experiment template with compiled examples. The app can adopt the route/matching fixes independently, but I would fix keyword-order preservation, domain binding, and seniority detection before presenting the new controls as fully effective user settings. See [report.md](report.md) and [generic-profile-usage.md](generic-profile-usage.md) for results and usage boundaries.
