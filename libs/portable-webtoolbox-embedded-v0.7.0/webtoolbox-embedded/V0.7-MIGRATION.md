# v0.7 migration — job posting discovery

The package remains an **importable async class**. No standalone process, HTTP server, or browser was added. The host application remains responsible for durable job tracking, resuming cancelled work, scheduling its five-job discovery queue, and persisting accepted matches.

## 1. Use the additive inputs

- `discover_job(..., keyword_mode="rank")` (default) sorts keyword matches. Pass `keyword_mode="filter"` to enforce the profile's required/excluded keywords for underlying search results.
- `search_title` affects generated queries **only**. `title` remains the full tracked role for final matching; `contract_type`, `reference`, `location`, and `seniority` are independent constraints.
- Optional `employer_context=EmployerContext(company="Acme", domain="acme.fr", status="confirmed", evidence_source="user_confirmed")` can provide domain verification. Unconfirmed domains and ISCOD publisher identity never silently certify the employer.
- Set `Settings.max_job_discovery_pages` to adjust the job ceiling. `max_crawl_pages` controls contact research, not job discovery. The result reports both `requested_page_cap` and `effective_page_cap`.
- Edit `job_queries` and `keywords` in a JSON profile. Contact-only `page_positive` and `page_negative` do not rank job-discovery candidates; `job_closed`, `job_apply`, `job_blocked` apply to status checks and need separate validation before customization.

## 2. Consume the richer return envelope

- Read `matches` for candidate **individual posting** URLs. Each match includes `posting_url`, source-scoped `posting_identity`, `identifier`, `declared_canonical_url`, `schema_posting_url`, `redirected_from`, `instance_equivalence`, `application_links`, and `application_url`. An ATS `/apply` form is **not** a separate posting; see `application_destinations` when no parent was established.
- Store alternatives separately until exact source ID/reference, a tested redirect, or explicit cross-link supports an equivalence relationship. Matching title/company alone is insufficient.
- Check `match.hard_conflicts` and `match.employer_identity` before offering a replacement posting. Definite employment contract, city, employer, reference and seniority conflicts lower confidence regardless of title similarity.
- Distinguish `route_rejections`, `untried_queries`, `query_stop_reason`, `inspected_page_count` and `unvisited_candidates`; never translate absence from search, exhausted budget or rate limiting into a confirmed closed posting.
- Check `search_attempts[*].http_status` and `cached_failure` to distinguish genuine 401/403/429 observations from `deferred_host_cooldown` (which is **not** another observed 429). An observed 404/410 refers to **that exact URL** only.
- Results may be compacted by `max_tokens`; check `truncation` and `completion=partial` before assuming every candidate was included.
