# Web Toolbox v0.6 — integration notes

The toolbox is still an **embedded** Python package. No HTTP server, Docker service, external search API key, or persistent job queue is required. Continue importing and scheduling its async methods in your application; the host owns durable retries and worker concurrency.

## 1. Employer evidence comes before outreach

Use `EmployerContext` when an application confirmation, the original posting, or a user-confirmed website establishes the employer domain.

```python
from webtoolbox import EmployerContext

# Only mark this confirmed when the evidence actually establishes the domain.
context = EmployerContext(
    company="Atos",
    domain="atos.net",
    status="confirmed",
    evidence_source="user_confirmed",
    aliases=("Atos SE",),
)

# Pass the context to the existing async WebToolbox instance.
result = await web.research_contacts("Atos", employer_context=context, pages=3)
```

An `official_domain="atos.net"` argument *without* `employer_context` still limits browsing to that domain, but sets employer identity to `provisional`: candidate records are returned for review and `recommended_count=0`. This is an intentional safety change from 0.5. Bare employer names do not certify `atos.net` over `atos.com`. The toolbox cannot independently certify a claimed legal entity or employer-to-ATS relationship.

If there is no known domain, results are unverified leads. The caller should prompt for human confirmation or extract provenance from real application correspondence. `excluded_domains` shows excluded hosts (up to 15, for token limits). Source-provided legal-name information is treated as evidence, not authoritative registry verification.

Crawl-budget diagnostics: `page_budget_exhausted`, `unvisited_pages`, `completion`, `stop_reason` and `crawl_attempts`. `partial` means a result set is incomplete, not that the fetcher crashed.

## 2. Set keywords without changing Python source

Place the bundled `profiles/alternance_it.example.json` in your app's own settings/config directory. Load it with `Settings(keyword_profile=Path(...))`, or pass `keyword_profile=Path(...)` directly to `search`, `crawl`, `research_contacts`, `search_with_fallback`, `discover_job`, or `check_job_status`.

```python
from pathlib import Path
from webtoolbox import Settings, WebToolbox

# One reusable instance per app; the profile is not global process state.
web = WebToolbox(Settings(keyword_profile=Path("config/alternance_it.json")))

# Soft ranking keeps potential leads; strict filtering is an explicit choice.
ranked = await web.search("alternance Python Toulouse", keyword_mode="rank")
filtered = await web.search("alternance Python Toulouse", keyword_mode="filter")
```

Supported profile sections:

| Key | Behavior |
| --- | --- |
| `contact_recruitment`, `contact_exclusions` | Purpose classification for found addresses |
| `vacancy_confidentiality` | Vocabulary that identifies confidential vacancy notices as recruitment rather than privacy requests |
| `recruiter_titles` | Replace ranked recruiter-role title phrases |
| `page_positive`, `page_negative` | Rank or reject linked pages and search frontiers |
| `contact_queries`, `job_queries` | Bounded fallback query templates |
| `job_closed`, `job_apply`, `job_blocked` | Customize job status and application-button detection |
| `keywords.required`, `keywords.preferred`, `keywords.excluded`, `keywords.synonyms` | Ranked or strict search result filters |

Lists replace their defaults; omitted keys preserve defaults. Search fields accept `{company}`, `{role}`, `{domain}`, `{title}` and `{location}` in the relevant methods. Always preserve the contact-evidence rules and review keyword changes before strict filtering—especially in multilingual company names. Keywords do not verify a company's identity, a job's current status, or an email's deliverability.

## Compatibility and operational limits

Existing `WebToolbox(Settings())`, `.crawl()`, `.search()`, `.research_contacts()`, `.discover_job()` and `.check_job_status()` calls remain import-compatible. Evidence-based `outreach_eligible` and `recommended_count` are intentionally stricter without a confirmed employer context. `mode="auto"` does not launch Chromium. Confirmed company domains can be researched even when search queries return empty results, by crawling the supplied homepage and its actual discovered links.

Only offline tests have been run here. Run live tests on the target installation to check DDGS, browser rendering, rate limits and real employer pages; avoid mailing or automatically applying during testing.
